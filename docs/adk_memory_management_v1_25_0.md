# Google ADK 1.25.0 以降のメモリ管理と自動コンパクション（圧縮）機能の調査結果

調査対象モジュール: `google-adk` (Version 1.25.1 にて実装を確認)
調査対象ファイル:
- `google/adk/apps/app.py`
- `google/adk/apps/compaction.py`

## 1. 機能概要

Google ADK では、LLMエージェントとのセッション履歴が長くなるとコンテキストウィンドウ（トークン数）の制限を超過したり、レイテンシやコストが悪化する問題を防ぐための仕組みが備わっています。
1.25.0 で新たに「トークン数に応じた自動コンパクション」と「直近イベントの保持（Retention）」機能が追加され、メモリ管理がより柔軟かつ確実に行えるようになりました。

## 2. 実装と設計の詳細

エージェントなどのトップレベルコンテナである `App` クラスには、`EventsCompactionConfig` という設定オブジェクトを渡すことができます。これまでも設定可能な `compaction_interval` (特定回数のターンの経過で圧縮) や `overlap_size` に加え、新たに以下のプロパティが追加・活用されています。

### 追加された主要な設定（`EventsCompactionConfig`）

*   **`token_threshold`** (int)
    *   **役割**: トリガーとなるトークン数の閾値。
    *   **動作**: セッション内の推定プロンプトトークン数（または LLM から返された直近の `usage_metadata.prompt_token_count`）がこの値以上の閾値に達すると、イベントの自動コンパクション（圧縮）処理が発火します。
*   **`event_retention_size`** (int)
    *   **役割**: コンパクション時に、圧縮せずにそのまま保持する直近の生イベントの数。
    *   **動作**: この値で指定された直近のN個のイベントは圧縮対象から除外され、そのままセッション履歴の末尾に残ります。
*   **制約**: 上記2つのパラメータは連動しており、どちらか一方だけを設定することはできず、必ず両方セットで設定する必要があります。

### コンパクションの評価と実行ロジック (`compaction.py`)

自動コンパクションは以下の設計で動作します。

1.  **プロンプトトークン数の推定 (** `_estimate_prompt_token_count` **)**
    *   APIから返された正確なトークン使用量が取得できている場合（`usage_metadata.prompt_token_count` が存在する場合) は、それを採用します。
    *   取得できない場合は、現在のセッション内のすべての未圧縮イベントのテキスト文字数をカウントし、**文字数 ÷ 4** を概算のトークン数として計算するヒューリスティックなフォールバックも備わっています。

2.  **圧縮対象の選定とローリング要約 (** `_run_compaction_for_token_threshold` **)**
    *   トークン数が閾値 (`token_threshold`) を超えた場合、未圧縮の生イベントのリストの先頭から、直近の `event_retention_size` 個のイベントを **除外した** 残りの古いイベントが圧縮対象として抽出されます。
    *   **ローリング要約 (Rolling Summary)**:
        セッション履歴に過去の圧縮イベント（要約）が既に存在する場合、その過去の要約内容も新たな要約作成のシード（入力）として引き継がれます。これにより、古い記憶が1つの「要約イベント」として集約・更新され続け、肥大化を防ぎます。
    
3.  **LlmEventSummarizer による要約の実行**
    *   設定されていなければ、デフォルトで `root_agent` のカノニカルモデルを使用して、抽出された古いイベント（および過去の要約）を `LlmEventSummarizer` によって新しい `CompactedEvent` にまとめます。
    *   作成された要約イベントは、セッション履歴に挿入（または既存要約と置換）され、以後のコンテキストに渡されます。

## 3. 結論・まとめ

新機能により、「特定ターン数」という静的なトリガーに加え、「実際に消費しているトークン数」を基準により動的かつ安全にコンパクションが行えるようになりました。  
また、`event_retention_size` による「直近の文脈の確実な保持」と「ローリング要約による過去の履歴の統合」を組み合わせることで、**モデルの長期記憶を維持しつつ、安全にコンテキスト限界の超過を防ぐ高機能なメモリ管理** を実現しています。

アプリ開発者は `App` 初期化時に以下のように設定することでこの機能を有効化できます。

```python
from adk.apps.app import App, EventsCompactionConfig

app = App(
    name="my_agent_app",
    root_agent=my_agent,
    events_compaction_config=EventsCompactionConfig(
        compaction_interval=5, # 互換性のための既存設定
        overlap_size=1,        # 互換性のための既存設定
        token_threshold=8000,       # 追加機能: 8000トークンを超過したら圧縮
        event_retention_size=4      # 追加機能: 直近の生イベント4つは圧縮せずにそのまま維持
    )
)
```
